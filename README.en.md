# Black Mesa SourceMod Plugin Collection

English | [中文](README.md)

SourceMod plugins for a **Black Mesa Deathmatch server**: 36 modules compiled into a single `BMAG.smx`,
plus a few standalone plugins loaded separately. Prebuilt artifacts are on
[Releases](https://github.com/MXYLR/MXYLR-Black-Mesa-Sourcemod-plugins/releases).

## Directory layout

│   ├── fix_merge.py              patch tool for merge.py

│       ├── include/              SourceMod includes used for compiling
│       ├── BMAG/                 merge.py output (.sp and module copies not committed, .smx is)

`.gitignore` only excludes the intermediate build product generated by `merge.py`
(`src/scripting/BMAG/*.sp`) and the shelved custom-crosshair client mod `client_mod/`; the toolchain,
evidence dumps, the old delivery package and `campaign/` are all committed.

## Installation

```bat
set SRV=<your srcds root>
copy /Y plugins\BMAG.smx            %SRV%\bms\addons\sourcemod\plugins\
copy /Y plugins\bms_rpgReloadFix.smx       %SRV%\bms\addons\sourcemod\plugins\
copy /Y plugins\bms_weapon_tauStuckFix.smx %SRV%\bms\addons\sourcemod\plugins\
copy /Y plugins\is_weaponfx.smx            %SRV%\bms\addons\sourcemod\plugins\
copy /Y plugins\is_bms_fix_timelimit.smx   %SRV%\bms\addons\sourcemod\plugins\
copy /Y smx_analysis\src\scripting\translations\*.txt %SRV%\bms\addons\sourcemod\translations\
copy /Y smx_analysis\src\scripting\gamedata\bms_match.games.txt %SRV%\bms\addons\sourcemod\gamedata\
copy /Y smx_analysis\src\scripting\configs\bms_match.cfg %SRV%\bms\addons\sourcemod\configs\
copy /Y smx_analysis\src\scripting\cfg\*.txt             %SRV%\bms\cfg\
copy /Y smx_analysis\src\scripting\cfg\*.cfg             %SRV%\bms\cfg\
```

Launch: `srcds.exe -game bms +map dm_boom +maxplayers 16 -condebug`.

Notes:

- Every `.smx` except `BMAG.smx` is a **standalone plugin, not part of BMAG**, and must be copied separately
- `translations/*.txt` are read at runtime and are **not compiled into `BMAG.smx`**; without them chat shows raw phrase keys
- `bms_match.games.txt` provides the signature-based addressing for `CGameRules::SetState`; **do not rename it**
  (`LoadGameConfigFile` only appends `.txt`)
- Disable SourceMod's bundled `plugins/nextmap.smx`: on this server map changes are decided by `bms_match`'s
  votes plus the core's `sm_nextmap`
- `is_weaponfx.smx` needs `is_weaponfix_saddr` set explicitly in `server.cfg` (the default value is treated
  as "not configured" and it disables itself)
- Permission flag `b` = generic admin; the full table is in `configs/admin_levels.cfg`
- The configs still carry **the original server's name, group number, domain and placeholder SteamIDs**.
  Change them before running a public server (`cfg/server.cfg`, `configs/admins.cfg`,
  `configs/advertisements.txt`, `motd/index.html`; search for `>>>`)

## ① `bms_match` — match plugin (in-house)

A match system rewritten against the Black Mesa engine, using hl2dm's xms match plugin as a reference.
It is a module **inside `BMAG.smx`** and **cannot be loaded standalone**.

### Player commands

| Command | Description |
|---|---|
| `!start` | Start a match. If the player count reaches `VoteMinPlayers`, a vote is started; otherwise (with bots, at least 2 players) it starts directly |
| `!cancel` | Cancel the match and restore public-server settings. During a match this requires a vote |
| `!help` / `!commands` | Open the match command menu (as a radio menu) |
| `!maplist` / `!list [mode]` | Show the map pool, `ffa` / `tdm` / `all`, default is the current mode |
| `!run <map>` / `!runnow <map>` | Start a "change the current map" vote; accepts `mode:map` and abbreviations |
| `!runnext <map>` | Start a "set the next map" vote |
| `!runrandom` | Draw 4 random maps from the current mode's pool and start a change-map vote |
| `!shuffle` | Shuffle the teams (TDM only) |
| `!invert` | Swap the two teams (TDM only) |
| `!yes` / `!no` / `!1`–`!5` | Vote |
| `!pause` / `!unpause` | Pause / resume the server |
| `!panel` / `!webpanel` | Open the in-game web console |

**Chat aliases**: `!stop` → `!cancel`, `!join` → join the smaller team, `!spec` → spectate,
`!next <map>` → `!runnext <map>`, `!random` → `!runrandom`.

Map abbreviations accepted by `!run`: `bunker`→`dm_lambdabunker`, `bounce`, `stalk`→`dm_stalkyard`,
`sub`→`dm_subtransit`, `gas`→`dm_gasworks`, `rail`, `crossfire`, `boom`.

### Admin commands (require `b`)

| Command | Description |
|---|---|
| `!forcespec <player>` | Force a player into spectator |
| `!allow <player>` | Let a player join the match (lift the post-start join lock) |
| `!starttest` | Start a **1-minute** test match, used to verify the SourceTV recording chain |

### Match flow

1. `!start` → fewer than `VoteMinPlayers` players starts directly, otherwise a vote is started
2. MatchWait: run `exec server_match` (reset time limit / caps / respawn) → freeze players and strip their
   weapons → 4-second countdown
3. Match: the timer starts and teams lock; a disconnect auto-pauses; FFA is decided by most kills (ties by
   deaths), TDM by team score
4. A tie → automatic overtime, extended a minute at a time until someone wins
5. End: broadcast the winner and score → `exec server_match_post` restores public-server settings →
   automatically start the next-map vote

Matches automatically record SourceTV demos into the server-local `demos\` directory and broadcast the
filename afterwards; with `DownloadBase` set in `bms_match.cfg` they can be downloaded from FastDL's `/demos`.

**Single-player campaign maps are skipped automatically** (test: the `bm_c<digit>` prefix, 78 campaign maps):
team enumeration is skipped, the 1 Hz timers are silenced, and `fast_spawn`, `advertisements`,
`connectmessage` and `showhealth` are turned off.

### Status page (persistent HUD info)

Redrawn once per second: `health/armor`, match state, countdown, map, held-weapon ammo (including MP5
grenades); while dead/spectating it draws the observed player instead, and channel 2 also appends your own
K/D / ping and the top-5 board.

| ConVar | Default | Description |
|---|---|---|
| `bms_status_page` | 2 | 0 = off; 1 = only dead/spectating players see it; 2 = everyone |
| `bms_status_channel` | 0 | 0 = hint panel (boxed, multi-line; each message replays the appear animation, so it looks like it flickers); 1 = HudMsg (no box, 6 lines); 2 = compact HudMsg (+ K/D / ping / top-5) |
| `bms_status_keyhint` | 1 | Panel used by channel 0: 1 = `KeyHintText` (narrow box, multi-line); 0 = `HintText` (the same thin bar as Show Health — silent and flicker-free, but single-line only) |
| `bms_status_hintsound` | 0 | 0 = silence the hint panel; 1 = leave players' own settings alone |
| `bms_status_stats` | 1 | Channel 2 appends K/D / ping and the top-5 board |
| `bms_status_right` | 0.89 | Right edge of the HudMsg text block (fraction of screen width; 16:10 max ≈ 0.91, 16:9 ≈ 0.82) |

### Other ConVars

| ConVar | Default | Description |
|---|---|---|
| `sm_bms_webpanel_enabled` | 1 | Enable the in-game web console (requires the socket extension) |
| `sm_bms_webpanel_host` | *(empty)* | Host used in the panel URL; empty = `127.0.0.1` |
| `sm_bms_webpanel_port` | 28015 | Web console listening port |

### Configuration (`configs/bms_match.cfg`)

| Key | Default | Description |
|---|---|---|
| `VoteMinPlayers` / `VoteMaxTime` / `VoteCooldown` | 3 / 25 / 30 | Vote player threshold, duration, cooldown (seconds) |
| `AutoVoting` | 1 | Automatically start the next-map vote after a match |
| `DefaultMode` / `RetainModes` | ffa / ffa,tdm | Default mode / modes retained across map changes |
| `PreMatchCommand` / `PostMatchCommand` | `exec server_match` / `exec server_match_post` | Cfgs run before / after the match |
| `Gamemodes` | — | Per mode: `Command`, `Mapcycle`, `Defaultmap`, `Matchable`, `Overtime`, `MatchTimelimit` |
| `Maps` | — | `StripPrefix`, `DefaultModes`, `Abbreviations` |

## ② Other self-written / heavily modified modules (10)

All **compiled inside `BMAG.smx`** and not loadable standalone. `spawn_distribute` and `textmsg_fix` are
in-house; the rest are adapted from AlliedModders community plugins (`fast_spawn` and `speclist` from
Alienmario, `SpecDetails` from wribit, `missing_viewmodel_fix` from ch4os + SHUFEN, `advertisements` from
Tsunami).

| Module | One-liner |
|---|---|
| `fast_spawn` | Zero-second respawn, no waiting for the native keypress or 5-second `mp_forcerespawn` |
| `spawn_distribute` | Even spawn-point distribution, fixing the native pile-up on one point |
| `textmsg_fix` | `_vsnprintf` crash from UTF-8 Chinese messages under CP936 |
| `adv-weapon_cleaner` | Dropped-weapon sweep |
| `SpecDetails` | Spectator details (left-hand panel) |
| `speclist` | Spectator list |
| `missing_viewmodel_fix` | Rebuild the viewmodel after a team / spectator switch |
| `advertisements` | Rotating ads |
| `sm_noearbleed` | Remove explosion ringing/muffling |
| `spawn_marker` | Spawn-point landing markers (training aid, off by default) |

### `fast_spawn` — zero-second respawn

| Command | Permission | Description |
|---|---|---|
| `fastspawn` / `sm_fs` | b | Query or toggle zero-second respawn |

| ConVar | Default | Description |
|---|---|---|
| `sm_fastspawn` | 1 | Enable: respawn `sm_fastspawn_time` seconds after death |
| `sm_fastspawn_batch` | 4 | Max players respawned per game tick (lower is smoother) |
| `sm_fastspawn_time` | 0.0 | Respawn delay in seconds (0 = immediate) |

When a real player is killed, **all six weapon slots are dropped on the ground** (bots keep the native
single-weapon drop). Automatically disabled on single-player campaign maps and during matches.

### `spawn_distribute` — even spawn-point distribution

The native spawn-point selection chain is broken (`IsSpawnPointValid` never reads the spawn flags and uses
a zero-length trace to test occupancy), so everyone is dumped on the same point. This module leaves the
native logic alone and picks a free point itself in `player_spawn`.

| ConVar | Default | Description |
|---|---|---|
| `spawn_distribute_enabled` | 1 | Enable |
| `spawn_distribute_cooldown` | 2.0 | How long the same point is not reassigned after use |
| `spawn_distribute_radius` | 64.0 | Real-player occupancy radius (bots don't participate) |

### `textmsg_fix` — Chinese crash fix

Fixes the `_vsnprintf` fail-fast crash caused by dangling lead bytes from UTF-8 Chinese messages under the
CP936 code page. No commands, no ConVars.

### `adv-weapon_cleaner` — dropped-weapon sweep

| ConVar | Default | Description |
|---|---|---|
| `adv_weapon_cleaner_keep_map_weapons` | 1 | Keep weapons that belong to the map (0 = remove, 1 = keep) |
| `adv_weapon_cleaner_much_weapons` | 100 | Weapon count threshold that triggers cleanup |
| `adv_weapon_cleaner_remove_delay` | 20.0 | How long to wait before removing a dropped weapon |
| `adv_weapon_cleaner_remove_delay2` | 0.1 | Per-weapon decrementing delay |
| `adv_weapon_cleaner_sweep_interval` | 10.0 | Full-sweep interval in seconds (0 = off) |

Only tracks `weapon_*` and never removes `item_*` (chargers, pickups).

### `SpecDetails` — spectator details

`sm_specDetails_enabled` (default 1). Automatically disabled during matches (panel updates have a 5-second
cooldown).

### `speclist` — spectator list

No commands, no ConVars. Periodically refreshes the spectator roster.

### `missing_viewmodel_fix` — missing held-weapon model fix

No commands, no ConVars. Hooks `jointeam` and `client_specmode` and rebuilds the viewmodel after a
team / spectator-mode switch.

### `advertisements` — rotating ads

| Command | Permission | Description |
|---|---|---|
| `sm_advertisements_reload` | b | Re-read the advertisement file |

| ConVar | Default | Description |
|---|---|---|
| `sm_advertisements_enabled` | 1 | Enable/disable |
| `sm_advertisements_file` | advertisements.txt | The ad text file |
| `sm_advertisements_interval` | 30 | Seconds between ads (this server sets 600) |
| `sm_advertisements_random` | 0 | Play in random order |

### `sm_noearbleed` — remove explosion ringing / muffling

No commands, only `sm_noearbleed_version`. Hooks `OnTakeDamage` and changes `DMG_BLAST` into `DMG_GENERIC`
(damage numbers untouched).

### `spawn_marker` — spawn-point landing markers (off by default)

Training aid: on `player_spawn` it marks the point the player **actually landed on**.

| Command | Permission | Description |
|---|---|---|
| `sm_spawnmarker` | b | Toggle spawn-point markers |
| `sm_spawnmap` | b | Toggle permanent display of all spawn points |
| `sm_sm` | b | Shorthand alias |

| ConVar | Default | Description |
|---|---|---|
| `sm_spawnmarker_enabled` | 0 | Enable spawn-point markers |
| `sm_spawnmarker_life` | 5.0 | How long a marker stays (seconds) |
| `sm_spawnmarker_spawnmap` | 0 | Continuously display all Deathmatch spawn points |

## ④ Standalone plugins

### Single-player campaign plugins (`campaign/`)

The tau cannon is "castrated" in the single-player campaign: no gauss jump, and the secondary attack has a
delay — both branches are hard-coded in `server.dll` (decided by `IsMultiplayer()`), so no ConVar can change
them. The two plugins are independent and serve the campaign only:

| Project | What it does |
|---|---|
| `campaign/tau_mp/` | Gives the single-player tau the multiplayer **gauss jump** and **no right-click cooldown**, and caps **fall damage at 10 HP** |
| `campaign/hl1tau/` | Restores the tau splash radius to the HL1 value |

### Third-party plugins (no source)

| Plugin | Purpose |
|---|---|
| `bms_rpgReloadFix.smx` | RPG reload animation fix |
| `bms_weapon_tauStuckFix.smx` | Tau stuck-weapon fix at low ammo: on the first right-click tick while holding `weapon_tau`, top up the reserve ammo to 3 |
| `is_weaponfx.smx` | Weapon-animation prewarming (needs `is_weaponfix_saddr` set in `server.cfg`) |
| `is_bms_fix_timelimit.smx` | Round time limit fix (BM reads `mp_timelimit` only once at map load; this goes through the `mp_round_time` entity's add-time input) |

## Building from source

```bash
cd smx_analysis
python merge.py          # generates src/scripting/BMAG/BMAG.sp (36 modules merged)
```

Then compile with the bundled spcomp (`dl/sm-win/`):

```bash
./dl/sm-win/addons/sourcemod/scripting/spcomp.exe \
  -i "src/scripting/include" \
  -o "src/scripting/BMAG/BMAG.smx" \
  "src/scripting/BMAG/BMAG.sp"
```

Baseline: **48 warnings, 0 errors**.

Notes:

- spcomp output is **not byte-reproducible** — judge whether a build is current by functional testing or
  logs, never by comparing MD5s
- The `include/` directory must match the server's SourceMod version: older `sourcemod.inc` takes only 3
  parameters for `StoreToAddress` and will fail to compile
- **Signatures must be relocation-safe**: `GameConfGetAddress` scans loaded memory, so signatures containing
  absolute addresses (`imm32`) mismatch at runtime because of base relocations (they hit on disk, miss in
  memory, and silently do nothing). Verify with `smx_analysis/sig_check.py`
- `merge.py` only bridges **exact** forward names; `bms_match`'s `Bms_`-prefixed callbacks are mapped back to
  the standard names via `FORWARD_ALIASES`. When you rename a forward, update that table too or the callbacks
  silently stop firing
- The two campaign plugins' sources are under `campaign/`, outside `merge.py`'s scope, and are compiled
  separately
- `src/scripting/compile_all.sh` (compiles `plugins/*.sp` one by one) hard-codes `SPCOMP` to
  `/c/tmp/smx_analysis/...`, which does not exist in this repository; change it to the real
  `smx_analysis/dl/...` path before using it
